# تقرير الأداء (المهمة 13)

## كيف قيس
اختبار `PerformanceTests` (في `tests/Pharmacy.IntegrationTests/Reports`) يملأ قاعدة SQL Server حقيقية عبر خدمات النظام نفسها، ثم يقيس متوسط زمن كل عملية بعد تسخين خطة الاستعلام. لا يعمل ضمن التشغيل العادي للاختبارات؛ يُشغَّل بـ:

```powershell
$env:PHARMACY_PERF = "1"; $env:PHARMACY_PERF_PRODUCTS = "5000"
dotnet test tests\Pharmacy.IntegrationTests --filter "FullyQualifiedName~PerformanceTests"
```
النتائج تُطبع وتُكتب في `perf-results.txt` بجانب ملفات الاختبار. الأهداف: بحث المنتج < 300 ms، ترحيل فاتورة < 1 s، لوحة التحكم < 2 s، التقارير < 3 s.

بيئة القياس: جهاز تطوير واحد، SQL Server محلي (نفس الجهاز للتطبيق وقاعدة البيانات)، بلا حمل مستخدمين متزامنين.

## النتائج بعد التحسين

| العملية | 1,500 منتج | 5,000 منتج | الهدف |
|---|---|---|---|
| بحث منتج بالاسم | 14 ms | 18 ms | < 300 |
| قائمة المخزون (صفحة مفلترة) | 124 ms | 142 ms | < 500 |
| ترحيل فاتورة بيع | 27 ms | 7 ms | < 1000 |
| لوحة التحكم | 441 ms | 322 ms | < 2000 |
| تقرير الأرباح (الشهر) | 6 ms | 19 ms | < 3000 |
| تقرير المبيعات اليومية | 10 ms | 8 ms | < 3000 |
| تقرير المبيعات حسب المنتج | 12 ms | 10 ms | < 3000 |
| تقرير المخزون حسب الدفعة | 7 ms | 30 ms | < 3000 |
| فحص الحسابات (المطابقة) | 152 ms | 249 ms | < 10000 |

حجم البيانات في آخر قياس: 5,001 منتجاً، 5,001 دفعة، 2,500 فاتورة بيع (الملء استغرق نحو 3 دقائق).

## ما وُجد وعُدِّل
القياس الأول (1,500 منتج) أظهر بطئاً حقيقياً قبل التحسين:

| العملية | قبل | بعد |
|---|---|---|
| قائمة المخزون المفلترة | 773 ms (تجاوزت 500) | 124 ms |
| لوحة التحكم | 2,393 ms (تجاوزت 2000) | 441 ms |

**السبب**: تجميع كميات كل منتج (المتاح والمحجور والمنتهي وقريب الانتهاء والقيمة) يقرأ جدول الدفعات لكل منتج، والفهرس القائم لا يحوي الكميات فكان يعود لصفوف الجدول.
**الحل**: جعل فهرس `(ProductId, ExpiryDate)` على الدفعات **فهرساً شاملاً** (`INCLUDE` الكميات والتكلفة) عبر الترحيل `AddBatchCoveringIndex`، فتُقرأ الأرقام من الفهرس وحده.

## حدود هذا القياس (للأمانة)
- كل منتج فيه دفعة واحدة، والفواتير 2,500 فقط؛ لم أقس حجم **100 ألف فاتورة**. جداول الفواتير والحركات مفهرسة بالتاريخ والمستند، والتقارير تستعلم بتجميع في قاعدة البيانات، لكن يُنصح بإعادة القياس بعد سنة من التشغيل الفعلي بالأمر أعلاه (ارفع `PHARMACY_PERF_PRODUCTS` حسب الحاجة).
- القياس بمستخدم واحد؛ اختبارات التزامن (عدة مستخدمين على نفس الدفعة/الوردية) موجودة ضمن الاختبارات العادية وتتحقق من الصحة لا السرعة.
- التقارير التي تُحمَّل بالكامل في الذاكرة (المبيعات اليومية: تجميع بالتاريخ المحلي) محدودة بـ 50,000 صف وتطلب فترة أقصر عند تجاوزه.
- على الخادم الفعلي (SQL Server Express) قد تكون الأزمنة أعلى قليلاً بسبب حدود الذاكرة (1 جيجابايت للمحرك في Express)؛ لذا يُنصح بقرص SSD.
