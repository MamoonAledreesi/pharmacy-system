# النسخ الاحتياطي والاسترجاع

بيانات الصيدلية كلها في قاعدة SQL Server واحدة (`PharmacyDb`)، فنسخها كافٍ لاسترجاع كل شيء.

## النسخ اليومي
```powershell
.\deploy\register-backup-task.ps1 -BackupFolder D:\PharmacyBackups -At 02:00 -KeepDays 30
```
- يُنشئ مهمة مجدولة يومية تعمل بحساب SYSTEM، تنفّذ `deploy\backup.ps1`.
- كل نسخة **مضغوطة ومفحوصة بالمجموع الاختباري (CHECKSUM)**، ثم يُجرى عليها `RESTORE VERIFYONLY` فوراً للتأكد أنها تُقرأ.
- تُحذف النسخ الأقدم من `KeepDays` يوماً، وتُسجَّل النتيجة في `backup.log` داخل مجلد النسخ (OK أو FAILED).
- **اجعل مجلد النسخ على قرص مختلف عن قرص قاعدة البيانات**، ويُفضَّل نسخه أسبوعياً إلى قرص خارجي أو سحابة خارج الصيدلية.

نسخة يدوية في أي وقت (مثلاً قبل التحديث):
```powershell
.\deploy\backup.ps1 -BackupFolder D:\PharmacyBackups
```

## الاسترجاع
1. أوقف الخدمة: `Stop-Service PharmacySystem`.
2. (اختياري لكن مستحسن) خذ نسخة من الحالة الحالية قبل الاستبدال.
3. نفّذ:
   ```powershell
   .\deploy\restore.ps1 -BackupFile D:\PharmacyBackups\PharmacyDb-20261029-020000.bak
   ```
   يطلب كتابة `YES` لأنه **يستبدل** القاعدة الحالية.
4. شغّل الخدمة: `Start-Service PharmacySystem`.
5. افتح **فحص الحسابات** (قائمة الإدارة) وتأكد أن النتيجة مطابقة.

> ما أُدخل بعد وقت النسخة المسترجعة يضيع؛ لذلك النسخ اليومي مهم، وقد تحتاج لإعادة إدخال عمليات اليوم يدوياً.

## اختبار الاسترجاع (يُجرى مرة كل ثلاثة أشهر)
النسخة التي لم تُجرَّب ليست مضمونة. على جهاز اختبار (وليس الخادم الفعلي):
1. انسخ آخر ملف `.bak` إليه، وثبّت SQL Server.
2. `.\restore.ps1 -BackupFile ... -Database PharmacyDb_Test`
3. شغّل النظام على القاعدة المسترجعة (غيّر سلسلة الاتصال) وافتح فواتير وتقارير معروفة وقارن، ثم شغّل **فحص الحسابات**.
4. دوّن التاريخ والنتيجة.

## جدول الاحتفاظ المقترح
| النسخة | الاحتفاظ |
|---|---|
| يومية | 30 يوماً (على الخادم) |
| أسبوعية (يوم الجمعة مثلاً) | 6 أشهر (قرص خارجي) |
| شهرية | سنتان (خارج الصيدلية) |

## ملفات السجلات
سجلات التطبيق في `C:\Pharmacy\app\logs` (ملف لكل يوم، تُحفظ 90 يوماً). ليست جزءاً من نسخ قاعدة البيانات؛ انسخها عند التحقيق في مشكلة.
