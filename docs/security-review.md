# المراجعة الأمنية (المهمة 13)

نطاق المراجعة: التطبيق (Web/Application/Infrastructure) وإعدادات النشر على شبكة محلية. التاريخ: 2026-10-29.

## ما فُحص وما وُجد

| المجال | الفحص | النتيجة |
|---|---|---|
| المصادقة | ASP.NET Core Identity، كلمات المرور مجزّأة، قفل الحساب بعد محاولات فاشلة، كوكي `HttpOnly` و`SameSite=Lax`، مدة جلسة 12 ساعة | سليم |
| كوكي المصادقة | `Secure` دائماً خارج التطوير (لا يُرسل عبر HTTP) | **عُدِّل**: أُضيف `SecurePolicy=Always` في الإنتاج |
| التفويض | سياسة لكل صلاحية، تُفحص في الصفحات **وفي خدمات التطبيق** | سليم؛ **أُضيف اختبار آلي** يفحص أن كل صفحة تتطلب تسجيل دخول إلا الدخول والإعداد الأولي والخطأ، وأن كل نقطة نهاية محمية إلا المعروفة |
| الصفحات المفتوحة | `/Account/Login` و`/setup` (مرة واحدة ما دام لا يوجد مستخدم) وصفحتا الخطأ و`/culture/set` و`/health` و`/_blazor` | موثّقة في الاختبار `SecurityTests` |
| CSRF | Antiforgery على النماذج وتسجيل الخروج (يُرفض الطلب بلا رمز) | سليم، يغطيه اختبار |
| ترويسات الأمان | لم تكن موجودة | **أُضيفت**: `Content-Security-Policy` (مصادر من الموقع نفسه فقط، بلا CDN)، `X-Frame-Options: DENY`، `X-Content-Type-Options: nosniff`، `Referrer-Policy`، `Permissions-Policy`، وحُذف رأس `Server` |
| HTTPS | HSTS وإعادة التوجيه في الإنتاج؛ شهادة من مخزن Windows دون كلمة مرور في الملفات | موثّق في دليل التثبيت |
| حقن SQL | كل الوصول عبر EF Core بمعاملات؛ لا SQL نصي في الكود الإنتاجي | سليم |
| XSS | ترميز Razor الافتراضي؛ لا `MarkupString` لمحتوى المستخدم | سليم |
| الحزم | `dotnet list package --vulnerable --include-transitive` | **لا توجد حزم معرّضة** في كل المشاريع |
| الأسرار | لا أسرار في المستودع؛ سلسلة الاتصال فارغة افتراضياً وتُوضع في ملف الإنتاج أو متغير بيئة | سليم |
| السجلات | Serilog بملفات يومية (90 يوماً)؛ لا تُسجَّل كلمات المرور | سليم |
| التدقيق | العمليات الحساسة (موافقات المشرف، التعديلات، الإلغاء) تُسجَّل باسم المستخدم والوقت في المعاملة نفسها | سليم |
| سلامة البيانات | قيود CHECK في قاعدة البيانات، تزامن متفائل (rowversion)، مفاتيح منع التكرار للعمليات | سليم؛ **أُضيف تقرير مطابقة** (الإدارة ← فحص الحسابات) يكشف أي تعديل خارج النظام |
| تصدير البيانات | نقطة التصدير تتطلب تسجيل دخول و`Reports.Export` (وصلاحية التكلفة لتقارير الربح) | سليم، يغطيه اختبار |
| الاستضافة | `AllowedHosts` تُضبط على اسم الخادم في ملف الإنتاج | قالب جاهز في `deploy/` |

## حدود معروفة وتوصيات
1. **سياسة CSP تسمح بـ `unsafe-inline`** للنصوص والأنماط، لأن إطار Blazor وMudBlazor وأزرار الطباعة تستخدمها. الحماية الأساسية (منع تحميل أي نص من موقع خارجي، ومنع التضمين في إطار) قائمة.
2. **لا مصادقة ثنائية**، والنظام مصمَّم لشبكة محلية موثوقة. لا تعرّضه للإنترنت مباشرة؛ إن لزم الوصول عن بُعد فعبر VPN.
3. **الشهادة الموقّعة ذاتياً** تتطلب تثبيتها على الأجهزة العميلة؛ يُفضّل شهادة من مرجع داخلي إن وُجد نطاق.
4. **النسخ الاحتياطية غير مشفّرة** في ملفاتها؛ فعّل **BitLocker** على قرص النسخ، وأبعد نسخة أسبوعية عن الصيدلية.
5. **حساب الخدمة** يملك `db_owner` على قاعدة النظام فقط (لازم لترقية الجداول)؛ لا تمنحه أكثر.
6. **كلمات مرور الموظفين**: سياسة الطول والتعقيد مفروضة؛ يُنصح بتغييرها دورياً وعدم مشاركة الحسابات (التدقيق يعتمد على اسم المستخدم).
7. أبقِ Windows وSQL Server محدّثين، وأعد تشغيل `dotnet list package --vulnerable` عند كل إصدار.

## ما أُضيف في هذه المراجعة (ملخص التعديلات)
- `SecurityHeaders` (ترويسات الأمان)، وإخفاء `Server`، وكوكي `Secure` في الإنتاج.
- `SecurityTests`: ترويسات، كوكي، تدقيق آلي لكل الصفحات ونقاط النهاية، حماية الخروج، وإعادة التوجيه لغير المسجَّلين.
- تقرير المطابقة وصلاحيته `Reconciliation.Run` (للمدير والمحاسب افتراضياً).
- دعم التشغيل كخدمة Windows، وترقية القاعدة التلقائية عند الإقلاع في الإنتاج (`Database:MigrateOnStartup`).
