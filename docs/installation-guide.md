# دليل التثبيت على الشبكة المحلية

يصف هذا الدليل تثبيت النظام على جهاز خادم واحد داخل الصيدلية، تتصل به أجهزة الصيدلية (الكاشير والمخزن والمحاسب) عبر المتصفح.

## 1) المتطلبات
- **الخادم**: Windows 10/11 أو Windows Server 2019 فأحدث، 8 جيجابايت ذاكرة فأكثر، قرص SSD، ويُفضَّل جهاز مخصص يبقى شغّالاً.
- **SQL Server**: نسخة Express تكفي لصيدلية واحدة (حد 10 جيجابايت)، تُثبَّت كنسخة افتراضية `.` أو بنسخة مسمّاة.
- **.NET 10 Hosting Bundle** (ASP.NET Core Runtime) على الخادم.
- **الأجهزة العميلة**: أي متصفح حديث (Edge أو Chrome). لا حاجة لتثبيت شيء عليها.
- شبكة محلية بسعة معقولة؛ الخادم بعنوان ثابت أو باسم (مثلاً `pharmacy.local`).

## 2) تجهيز قاعدة البيانات
1. ثبّت SQL Server، وفعّل **TCP/IP** إن كانت الأجهزة الأخرى ستتصل به مباشرة (غير لازم عادةً، لأن التطبيق وحده يتصل بقاعدة البيانات).
2. اترك إنشاء القاعدة للتطبيق: عند أول تشغيل مع `Database:MigrateOnStartup=true` يُنشئ القاعدة `PharmacyDb` وجداولها، وكذلك يرقّيها عند كل تحديث.
3. **حساب الاتصال بأقل صلاحيات**: شغّل الخدمة بحساب Windows مخصص (مثلاً `PharmacySvc`) وامنحه عضوية `db_owner` على قاعدة `PharmacyDb` فقط (التطبيق يحتاجها لإنشاء الجداول وترقيتها)، ولا تستخدم `sa` ولا حساب مدير الجهاز.

## 3) شهادة HTTPS (داخلية)
النظام يُقدَّم عبر HTTPS حتى لا تنتقل كلمات المرور نصاً على الشبكة.
1. أنشئ شهادة موقّعة ذاتياً باسم الخادم، من PowerShell بصلاحيات المدير:
   ```powershell
   $cert = New-SelfSignedCertificate -DnsName "pharmacy.local" -CertStoreLocation Cert:\LocalMachine\My -NotAfter (Get-Date).AddYears(5)
   ```
2. لتجنب تحذير المتصفح، صدّر الشهادة (بدون المفتاح الخاص) وثبّتها في **Trusted Root Certification Authorities** على كل جهاز عميل.
3. إن كان لديكم نطاق (Active Directory) فاستخدموا شهادة من مرجع الشهادات الداخلي بدل الموقّعة ذاتياً.

> الشهادة تُقرأ من مخزن Windows (`LocalMachine\My`) بالاسم الموضوع في `appsettings.Production.json`، فلا توجد كلمة مرور شهادة داخل الملفات.

## 4) نشر التطبيق
على جهاز التطوير:
```powershell
dotnet publish src\Pharmacy.Web -c Release -o C:\Pharmacy\app
```
انسخ مجلد `C:\Pharmacy\app` إلى الخادم (المسار نفسه أفضل)، ثم:
1. انسخ `deploy\appsettings.Production.template.json` إلى `C:\Pharmacy\app\appsettings.Production.json` وعدّل:
   - `ConnectionStrings:PharmacyDb`: اسم الخادم/النسخة (مثل `Server=.\SQLEXPRESS;...`).
   - `AllowedHosts`: اسم الخادم الذي يفتحه المستخدمون.
   - `Kestrel:...:Certificate:Subject`: اسم الشهادة نفسه.
2. امنح حساب الخدمة صلاحية **قراءة وتشغيل** على مجلد التطبيق، و**كتابة** على المجلد الفرعي `logs`.

## 5) تشغيله كخدمة Windows
من PowerShell بصلاحيات المدير:
```powershell
.\deploy\install-service.ps1 -AppFolder C:\Pharmacy\app
```
السكربت ينشئ خدمة `PharmacySystem` تبدأ تلقائياً مع الجهاز وتُعاد تشغيلها عند التعطل، ويفتح المنفذ 443 في الجدار الناري لشبكتي Private/Domain فقط.

إن أردت تشغيلها بحساب مخصص: من `services.msc` افتح الخدمة ← تبويب Log On ← اختر حساب `PharmacySvc`.

## 6) أول مدير للنظام
افتح `https://pharmacy.local` من أي جهاز: تظهر صفحة **الإعداد الأولي** (تظهر مرة واحدة فقط ما دام لا يوجد مستخدم). أنشئ حساب المدير بكلمة مرور قوية واحتفظ بها في مكان آمن. بعدها:
1. **الإعدادات**: اسم الصيدلية بالعربية والإنجليزية والهاتف والعنوان واللون.
2. **المستخدمون والأدوار**: أنشئ حساباً لكل موظف بالدور المناسب (كاشير، صيدلي، محاسب، أمين مخزن).
3. أدخل المنتجات والمخزون الافتتاحي ورصيد العملاء والموردين الافتتاحي.

## 7) النسخ الاحتياطي
سجّل مهمة النسخ اليومي مباشرة بعد التثبيت (انظر `docs/backup-and-restore.md`):
```powershell
.\deploy\register-backup-task.ps1 -BackupFolder D:\PharmacyBackups
```

## 8) قائمة فحص قبل التشغيل الفعلي
- [ ] يفتح `https://pharmacy.local` من جهاز آخر دون تحذير شهادة.
- [ ] `https://pharmacy.local/health` يعيد `Healthy`.
- [ ] أُنشئ المدير وغُيِّرت كلمة المرور الافتراضية إن وُجدت.
- [ ] الخدمة تعمل بعد إعادة تشغيل الجهاز.
- [ ] نُفِّذت نسخة احتياطية يدوية بنجاح وجُرّب استرجاعها على جهاز اختبار.
- [ ] جُرِّبت فاتورة بيع وطباعتها (A4 والإيصال) وتصدير تقرير.
- [ ] نُفِّذ **فحص الحسابات** (قائمة الإدارة) وظهرت النتيجة "كل الأرصدة مطابقة".
- [ ] مسار السجلات `C:\Pharmacy\app\logs` يُكتب فيه.

## 9) التحديث إلى إصدار جديد
1. خذ نسخة احتياطية يدوية (`backup.ps1`).
2. أوقف الخدمة: `Stop-Service PharmacySystem`.
3. انسخ ملفات الإصدار الجديد فوق القديمة **بدون** استبدال `appsettings.Production.json` ومجلد `logs`.
4. شغّل الخدمة: `Start-Service PharmacySystem`، وستُرقّى قاعدة البيانات تلقائياً.
5. افتح الصفحة الرئيسية وشغّل **فحص الحسابات**.

## 10) حل المشاكل الشائعة
| العَرَض | السبب والحل |
|---|---|
| الصفحة لا تفتح من جهاز آخر | الجدار الناري (المنفذ 443) أو اسم الخادم غير معروف؛ جرّب `ping pharmacy.local`. |
| تحذير شهادة | ثبّت الشهادة في Trusted Root على الجهاز العميل. |
| الخدمة تتوقف عند التشغيل | راجع `logs\pharmacy-*.log`؛ غالباً سلسلة الاتصال أو صلاحية قاعدة البيانات. |
| "Invalid host" | أضف اسم الخادم إلى `AllowedHosts`. |
| بطء مفاجئ | تأكد أن SQL Server غير مُقيَّد بالذاكرة، وأن القرص ليس ممتلئاً. |
